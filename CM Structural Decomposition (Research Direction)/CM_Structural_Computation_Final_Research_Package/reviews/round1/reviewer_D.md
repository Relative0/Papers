# Round 1 Reviewer D: Experimental methodology and exact algorithms

**Status:** internal AI role-based adversarial review of frozen Draft 1. Not an external referee, separate model, or independently recruited reviewer.

The lifecycle accounting is unusually careful for a prototype. It charges discovery even when the result is a flat fallback, and it does not recycle oracle headroom from a separate compiler experiment. Those are the strongest features. The chief weakness is not lack of a p-value; it is the very narrow experimental population and representation policy.

R1-D1: provide a fused count path before interpreting timing. A scalar-count baseline should not be contrasted only with an artifact method that first builds a new object if a fused operation is available. R1-D2: add binary serialization sensitivity without retuning to measured timing. JSON wins/losses are valid facts about JSON, not about storage lower bounds. R1-D3: clearly distinguish measured batch means, setup medians, and extrapolated T(Q); Q=1000 is not necessarily an actually executed thousand-query lifecycle.

Report per-case results rather than an overall geometric mean dominated by 32 flat fallbacks. The 26 outputs are a cluster from one design. There is no held-out confirmatory corpus and no basis for prevalence inference. A stronger baseline can only weaken a positive runtime claim; absence of CUDD does not invalidate a narrowly scoped failure to beat packed masks.

The fatal flaw test is hiding a dataset or selector change between revisions. Preserve the original protocol and raw results; write an amendment before the new run. Repeated trials in one shared container are descriptive; neither confidence intervals over circuits nor acceptance predictions are appropriate. My recommendation is report-only until a broader, separately frozen experiment exists.
