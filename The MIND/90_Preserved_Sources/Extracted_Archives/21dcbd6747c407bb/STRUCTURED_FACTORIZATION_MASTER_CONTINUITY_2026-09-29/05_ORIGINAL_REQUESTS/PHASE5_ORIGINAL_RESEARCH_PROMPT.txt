# 2. Baseline theorem

For a compressed SDD at vtree split X | Y,

    f(X,Y) = OR_i [ p_i(X) AND s_i(Y) ],

Phase 4 established the exact cut criterion:

    f(X,Y) = g(X) AND h(Y)

iff the compressed decision has at most one nonfalse sub.

Recursively applying this criterion yields the exact finest factorization whose blocks are vtree subtrees.

If every true semantic prime factor is a vtree subtree, this becomes the unrestricted full semantic prime partition.

Thus the key limitation is not correctness but VTree Alignment.

---

# 3. Baseline alignment problem

The fixed balanced four-variable vtree

    ((x0,x1),(x2,x3))

was tested against all nonfalse four-variable Boolean functions.

Among the decomposable functions, a large majority had unrestricted prime partitions strictly finer than the fixed-vtree-laminar partition.

Therefore:

    fixed arbitrary vtree
        !=
    reliable exposure of semantic prime factors.

The task is to determine how much of this gap can be closed automatically.

# 4. Central research questions

Investigate two increasingly strong goals.

## Goal A — direct-factor exposure

Construct/adapt a vtree T such that the compressed SDD exposes as much as possible of the true semantic prime factorization directly.

Measure:

- fraction of prime blocks exposed;
- fraction of attributes resolved without SAT;
- number and size of residual blocks;
- number of residual four-corner SAT queries.

## Goal B — prime alignment

Identify a meaningful semantic class C and a computable vtree construction A such that

    f in C
        =>
    every semantic prime factor of f is a subtree of A(f).

This is the theorem-level target.

If no meaningful class survives, document the boundary honestly.

---

# 5. Important upper-bound control

For any known semantic prime partition

    Pi_f = {B1,...,Bk},

one can construct a binary vtree in which each Bi is represented as a subtree.

Therefore an oracle given Pi_f can be made prime-aligned.

Use this as an UPPER-BOUND CONTROL.

The interesting problem is not existence of an aligned vtree.

The interesting problem is recovering useful alignment WITHOUT already knowing Pi_f.

# 6. Algorithms to compare

Implement and compare at least the following.

## A. Carrier-initialized vtree

Start from the simplicial carrier prime partition Pi_K.

Construct a vtree in which each carrier block is contiguous/a subtree.

Explore alternative arrangements of the carrier blocks:

- balanced;
- size weighted;
- interaction weighted.

Determine when the carrier helps and when it actively hides semantic factors.

## B. Semantic interaction graph/hypergraph vtree

Construct a variable interaction structure from the succinct semantic representation.

Possible edges/hyperedges:

- variables co-occurring in a CNF clause;
- variables sharing a circuit gate/module;
- ANF monomial co-occurrence where relevant;
- minimal known semantic interactions.

Use graph/hypergraph hierarchical clustering or separator methods to build the vtree.

Do not assume syntactic interaction equals semantic prime dependence.

## C. CM four-corner defect driven adaptation

Use four-corner witnesses from the exact SAT oracle.

A failed cut gives a nonzero rank-two defect.

Investigate how such witnesses can guide:

- vtree rotations;
- subtree merges;
- "must remain coupled" scores;
- local cut replacement;
- interaction-edge learning.

Be careful:

A failed cut proves that the whole cut is invalid; it does NOT automatically identify which particular variable pair caused the global failure.

Determine what additional minimization/querying is needed to turn a cut defect into a sound pairwise or module-level constraint.

## D. Carrier + semantic hybrid

Combine:

    carrier structure
    +
    syntactic semantic interactions
    +
    exact CM defect evidence.

Test multiple weightings, but preregister the benchmark protocol before examining held-out results.

## E. Local vtree rotations

Starting from A-D, optimize by standard/local vtree rotations.

Possible objectives:

- number of direct factors exposed;
- estimated residual SAT cost;
- SDD size;
- combination of compiled size and residual cost.

Avoid using the ground-truth prime partition in the objective except for oracle controls.

## F. Oracle prime-aligned vtree

Construct directly from the known exact Pi_f.

This is not an algorithmic competitor.

It is the upper-bound control answering:

"How much could vtree alignment help if it were perfect?"

# 7. Theorem attacks

Attempt to prove guarantees for identifiable semantic classes.

Candidates include, but are not limited to:

1. positive irredundant CNF;
2. formulas whose interaction-hypergraph components equal semantic prime factors;
3. bounded-treewidth factor graphs;
4. read-once formulas;
5. the support-disjoint CM/LM operator-tree class from Phase 4;
6. formulas composed from already certified independent modules;
7. hierarchical/block decomposable functions;
8. classes where all four-corner defects are localized to a known interaction graph.

For each positive theorem, ask whether it is genuinely stronger than:

"if you already know the factors, put them in vtree subtrees."

A theorem must provide a computable construction from weaker information.

---

# 8. Defect-localization subproblem

Treat this as a serious mathematical subproject.

Given a cut A | B with

    rank_F2 [f]_(A|B) > 1,

the four-corner SAT solver returns assignments witnessing a nonzero 2x2 minor.

Determine what can be inferred about the actual prime factor partition.

Investigate exact questions such as:

- Can a minimal subset of variables supporting the witness be recovered?
- Can repeated SAT calls produce a sound "must-link" edge?
- Can unsat/sat cores help?
- Can group testing identify a prime block crossing the cut?
- How many oracle queries are needed to localize the obstruction?
- Can carrier blocks reduce this problem to block-level localization?

A theorem of the form

    O(log n), O(k log n), or F(w) poly(n)

defect queries to identify a violated prime block would be especially interesting.

But do not force such a result.

---

# 9. Exact hybrid algorithm

The final algorithm should retain Phase 4's correctness discipline:

1. build/adapt vtree;
2. compile or emulate the compressed-SDD decomposition;
3. directly extract every factor certified by SDD structure;
4. combine with the carrier partition by exact LCC;
5. divide the unresolved problem into independent residual blocks;
6. invoke the persistent four-corner SAT oracle only inside unresolved blocks;
7. return the exact canonical simultaneous finest partition.

No heuristic vtree decision may cause an exact factor to be incorrectly discarded.

Heuristics may affect efficiency only, never correctness.

# 16. Success criteria

A strong theorem-level outcome is:

### A. Prime-alignment theorem

A computable vtree construction provably prime-aligns a meaningful semantic class.

or

### B. Defect-localization theorem

CM four-corner witnesses can be converted into exact structural information with a useful query/complexity bound.

or

### C. Hybrid complexity theorem

The adaptive vtree/direct-extraction method provably reduces the residual exact factorization problem under a useful parameter.

A strong empirical outcome is also acceptable:

### D. Reproducible hybrid improvement

On held-out instances, the method materially reduces a preregistered metric such as:

- residual SAT calls;
- residual variable volume;
- total hybrid runtime;
- or compiled size + residual solving cost,

without sacrificing correctness.

A valid negative outcome is:

### E. NO-GO

The tested vtree adaptation signals cannot reliably recover alignment beyond known decomposition/preprocessing techniques.
